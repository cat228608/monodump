# monodump

Дампер и инвокер для игр на **Unity с Mono** (не IL2CPP).

Показывает, что внутри игры: классы, поля (со смещениями и значениями статики),
свойства и методы — и позволяет **вызывать эти методы в живой игре**,
читать и писать поля. Без патчей байтов и без поиска адресов: мы просим сам
рантайм Mono сделать то, что умеет игра.

```
monodump.exe --process MyGame.exe --assembly Assembly-CSharp
```

## Зачем это

Классический путь в Cheat Engine — найти адрес значения, собрать цепочку указателей
или занопать код. В Unity-игре на Mono есть путь короче: вызвать
`QuestManager.CompleteAll()` или присвоить `Player.health = 999` по имени,
как это делает сама игра. monodump даёт список того, что можно вызвать,
и канал, чтобы это вызвать.

## Как это работает

Внешний процесс не может звать `mono_*` функции чужой игры, поэтому:

1. `monodump.exe` — инжектор. Находит процесс, пишет `monodump.ini` с опциями
   и грузит в игру payload.
2. `monodump_payload.dll` — работает уже внутри игры: находит модуль Mono,
   снимает дамп и следит за файлом команд.
3. Команды исполняются в **главном потоке игры** — иначе половина
   `UnityEngine` либо ничего не делает, либо роняет игру.

## Файлы релиза

| файл | для чего |
| --- | --- |
| `monodump.exe` | инжектор для 64-битных игр |
| `monodump_payload.dll` | payload для 64-битных игр |
| `monodump32.exe` | инжектор для 32-битных игр |
| `monodump_payload32.dll` | payload для 32-битных игр |

Разрядность payload должна совпадать с разрядностью игры. Файлы держи рядом друг с другом.

## Быстрый старт

1. Запусти игру и зайди в мир (в меню многие менеджеры ещё не созданы).
2. Запусти от имени администратора:

   ```
   monodump.exe --process MyGame.exe --assembly Assembly-CSharp
   ```

3. Смотри дамп: `dump.json` (и `dump.txt`) рядом с exe.
4. Найди интересное:

   ```
   python tools\monofind.py dump.json --grep quest --callable
   ```

5. Вызови его — допиши строку в `monodump_cmd.txt`:

   ```
   call QuestManager::CompleteAll on QuestManager::instance
   get Player::health on Player::local
   set Player::health 999 on Player::local
   ```

   Результат каждой команды ложится в `monodump_result.txt`.

## Команды

| команда | что делает |
| --- | --- |
| `call Класс::Метод аргументы` | вызывает метод |
| `get Класс::Поле` | читает поле |
| `set Класс::Поле значение` | пишет поле |
| `... on Класс::поле` | берёт экземпляр объекта из этого поля (обычно синглтон) |

Аргументы: `int`, `float`, `double`, `bool`, `string`, `char`, `IntPtr`, enum (числом), `null`.
Статические методы и поля работают без `on`.
Файл команд исполняется, когда заканчивается переводом строки, и после этого очищается.

## Флаги

| флаг | смысл |
| --- | --- |
| `--process <имя>` / `--pid <n>` | целевой процесс |
| `--list` | показать процессы с загруженным Mono |
| `--assembly <часть имени>` | фильтр сборок, почти всегда `Assembly-CSharp` |
| `--filter <часть имени>` | фильтр классов |
| `--out <папка>` | куда класть дамп и файлы обмена |
| `--no-dump` | не снимать дамп, только инвокер |
| `--quiet` | без консоли в игре, лог в `monodump.log` |
| `--oneshot` | снять дамп и выгрузиться |
| `--compile` | JIT-адреса методов (медленно) |

## Сборка

Нужны Visual Studio (C++ для рабочих столов) и CMake.

```
git clone --depth 1 https://github.com/TsudaKageyu/minhook third_party/minhook
build.bat
```

MinHook нужен для выполнения команд в главном потоке. Без него проект тоже соберётся,
но часть UnityEngine-вызовов работать не будет.

Результат: `build64\bin\Release` и `build32\bin\Release`.

## Подводные камни

- Только Mono. Если в игре есть `GameAssembly.dll` и `global-metadata.dat` — это IL2CPP,
  нужен другой инструмент.
- Если консоль в игре открыта, **не закрывай её крестиком** — умрёт игра.
  Для выгрузки нажми Enter или запускай с `--quiet`.
- Статические адреса и JIT-адреса в дампе верны только для текущего запуска игры.
- Сделай бэкап сейвов. Вызов методов в обход игровой логики может сломать прогресс.
- Только одиночная игра и свои игры. Не используй в онлайне и там, где есть античит.

## Структура

```
injector/main.cpp   инжектор (monodump.exe)
src/mono_api.*      поиск модуля Mono и его функций
src/dumper.*        обход метаданных и запись json/txt
src/invoker.*       разбор и выполнение команд
src/dispatch.*      выполнение в главном потоке игры (MinHook)
src/log.*           лог и файлы ответов
src/dllmain.cpp     жизненный цикл payload
tools/monofind.py   поиск по дампу
```
